# 世界公墓

一座永远不闭园的第一人称联网墓园。你走进去，为逝去的任何事物留一座纪念——一个人、一只生灵、一个地方、一件东西、一段关系、一个念头、一个时代，或者任何说不上类别的东西。别人的纪念也在那里，你可以停下来读，献一簇光，留一句话。来客是穿衣的人，可以下跪、鞠躬、合十、默哀，旁边的人看得到。

没有任务、等级、排行榜。只有走、看、立、读。

每座碑还能带一种声音（缝纫机、风扇、拍球、猫的呼噜、电视雪花）。走近三米才响，走开就淡掉。别人献光的时候，三十多米内的人都听得见远处传来一声钟，但看不见是谁——这是墓园里唯一能确认"刚才有人来过"的方式。

如果两个人恰好同时站在同一座碑前三米内，都站住不动满十秒，碑脚会推开一圈光，两个人都看得见。没有人说话，也没有人知道对面是谁。按 M 可以把所有声音关掉。

`ruleset: cyber-cemetery.p0.v1`

### 回声

立碑时可以多写一句「他说话的样子」——句子长短、爱用什么词、说话前先叹不叹气。写了这个，站在碑前三米内按 R，就能对他（它）说一句话，碑会用那个人的口吻回一句。

一座碑一次最多四句，然后它就走了。面板关掉，这些话不留在任何地方，也不写进档案。

这不是让 AI 假装活人。服务端的提示词写死了几条：不说自己是程序、不假装还活着、不承诺明天、不给时间地址、不编造人名和日期，被问到走了以后怎么样就轻轻带过。改这段提示词之前想清楚。

没留钥匙时，按 R 会提示「这块碑的回声只在立碑的人手里」，其它功能不受影响。服务端也可以配一把公共钥匙，让所有访客都能听见。

需要 Node 18 以上（本机已用 Node 22 验证）。

```powershell
cd "I:\赛博坟墓"
npm install
npm start
```

默认监听 `8787`，被占用时换一个端口：

## 名字和一句话（账号）

以前身份是浏览器里一个随机 id：换设备就换人，清缓存就失去对自己碑的所有权。现在门口有两行：

- **别人会这样称呼你的影子**——你的名字，所有人都看得见。
- **只有你知道的一句话**——不叫密码，也永远不上传明文；服务端只存它的 scrypt 哈希。

同名即同一账号：第二次用同一个名字和同一句话进门，就是你；名字被别人先占了，就是被占了。代价是：**没有邮箱、没有找回、不能改名**。想跨设备管自己的碑，就得记住这两样。

第一次登录时，如果这台浏览器里还留着旧的随机身份，服务器会把它名下所有的碑划到你的账号上，并告诉你「以前你在这儿留下的 N 座碑，现在归你了」。之后换哪台机器，只要两行写对，那些碑还是你的。

线上接口：

- `POST /api/account` `{name, secret}` → `{ok, uid, token, created}`；同名同秘密是 `created:false`，同名不同秘密会被拒：「这个名字已经有人用过。如果那是你，把当时那句话写对。」
- `POST /api/claim` `{token, legacyUid}` → 把旧身份名下的碑迁到账号上。

WebSocket 的 `join` 只认 `token`，不认客户端自报的 uid——否则任何人都能顶着别人的 uid 改别人的碑。手里没有有效 token 时仍然能走、能读碑、留言、献光，只是不能立碑。

`data/secret.txt` 是签发 token 的密钥，第一次运行自动生成。**删了它，所有人手里的 token 一起失效**（人和碑都还在，但得重新进门）；备份时别漏掉 `data/accounts.json` 和它。

## 森林、湖，和四种放法

墓园不再只有一块草地。西边有一片湖（半径 26 米）：湖盆是在地形里挖出来的一只碗，岸线很缓，水面比湖底高，人能蹚到小腿深，再往里就走不动了。三片林子加散落的树共八十多棵，全部走 InstancedMesh，只花三个 draw call；每棵树的位置由固定种子生成，所以在所有人的屏幕上，同一棵树都在同一处。

站在哪儿，决定这座碑能有几种放法：

| 放法 | 站在哪 | 它长什么样 |
|---|---|---|
| 立一块碑 | 任何空地 | 原来的四种碑型 |
| 埋在树根下 | 离树干 5 米内 | 一块木牌挂在树干上，树根旁一小堆土；每一棵树都可以是一个人的纪念 |
| 放在水面上 | 湖岸 10 米内 | 一条小船浮在水面，船尾一块小牌，船头一盏灯；船跟着水轻轻晃 |
| 放上天空 | 任何地方 | 一盏孔明灯升到 4~7 米停住，慢慢漂，火一直在抖；地上不再有一圈光 |

规则在服务端也校验一遍：船不能放到山上，树葬必须有树，石碑不能立进湖里。放不成的两种，按钮会变淡，按下去会告诉你为什么。葬法立下之后不能改——它已经在那儿了。

调试时可以把自己放到某处：`?spawn=x,z,yaw,pitch`（例如 `?spawn=-14,30,1.45` 站在湖岸）。

## 公网在线

这个服务是「静态页面 + WebSocket 实时同步 + JSON 持久化」的一体 Node 进程，任何能跑 Node 的地方都能托管。

### 方式一：临时公网地址（立刻能用，无需账号）

```powershell
.\tools\cloudflared.exe tunnel --url http://localhost:8899 --protocol http2 --no-autoupdate
```

日志里会出现一个 `https://xxx.trycloudflare.com`，把这个地址发出去就能多人同时进来。
注意：这是临时隧道，进程关掉地址就失效，Cloudflare 也不保证可用性；适合给人看一眼，不适合长期开园。

### 方式二：自己的服务器（长期开园）

```bash
# 服务器上
git clone / scp 整个目录上去
cd cyber-cemetery
docker build -t cyber-cemetery .
docker run -d --name cemetery -p 8787:8787 \
  -v $(pwd)/data:/app/data \
  cyber-cemetery
```

前面挂 Nginx 反代时，`/live` 这个 WebSocket 路径要带上 `Upgrade` / `Connection` 头：

```nginx
location / {
  proxy_pass http://127.0.0.1:8787;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_set_header Host $host;
  proxy_read_timeout 600s;
}
```

必须上 HTTPS，否则浏览器允许的页面来源受限，`wss://` 也起不来。

### 要多少人，要多大机器

瓶颈是**出站带宽**，不是 CPU。所有人每 125 ms 互相同步一次位置，带宽随人数约二次增长。

用 `tools/loadtest.mjs` 实压（`node tools/loadtest.mjs 50 15` 表示 50 人跑 15 秒，每人 12Hz 发 move）：

| 在线人数 | 峰值出站 | 服务端 CPU（单核占比） | 内存 | 建议 |
|---|---|---|---|---|
| 50 | 10 Mbps | 9% | 56 MB | 2 核 2G / 上行 10 Mbps |
| 100 | 40 Mbps | 22% | 71 MB | 4 核 4G / 上行 30-40 Mbps |
| 200 | 约 150 Mbps | 约 45% | 约 120 MB | 单进程 CPU 还够，但带宽必须先改成增量同步或二进制协议 |

压测数字来自本机 loopback，没有丢包和公网抖动，比真实环境乐观一些，选机器时留 30% 余量。

国内云主机 30 Mbps 固定带宽比机器本身贵得多。预算敏感就走海外或港新 VPS（2 核 4G、月流量 20 TB 那种，约 30-100 元/月），代价是国内直连 150-250 ms——来客隔着雾，移动钝一点几乎看不出来。静态资源（three.js、照片、录音）挂 CDN 可以把带宽从主机账上挪走。

### 该备份什么

`graves.json`、`accounts.json`、`secret.txt` 和 `uploads/` **必须一起备**：档案里只存媒体路径，只备 json 会得到一堆指着空文件的碑；漏掉 `secret.txt` 则所有人的 token 会一起失效。

服务启动时会自动做第一份快照，运行中每 24 小时再做一份，目录在项目根的 `backups/snapshot-<时间>/`，只保留最新 7 份。每份都包含上述四样，先写临时目录再改名，不会把半份快照当成正式备份。也可以随时手动执行 `npm run backup`。备份目录不要公开，也不要提交到仓库。

### 管理员藏起与恢复

公网开放前，在服务端设置只有你自己知道的 `CC_ADMIN_KEY`。没有配置时，管理接口返回 `admin_off`，完全关闭。

```bash
# 列出包括隐藏碑在内的简要档案
curl -X POST http://127.0.0.1:8899/api/admin/graves/list \
  -H "content-type: application/json" \
  -d '{"key":"你的管理钥匙"}'

# 藏起：公开列表与在线场景移除，互动全部拒绝；档案、照片、录音都保留
curl -X POST http://127.0.0.1:8899/api/admin/graves \
  -H "content-type: application/json" \
  -d '{"key":"你的管理钥匙","id":"碑的 id","hidden":true}'

# 恢复：把 hidden 改成 false
```

藏起不是删除，作者仍可在恢复后管理它；拆碑仍只有作者能做。管理钥匙不会进入浏览器或源码包。

### 方式三：云托管

任何支持常驻 Node 进程和 WebSocket 的平台都行（腾讯云 CloudBase 云托管、火山 IGA、Zeabur、Railway…）。要点只有三个：

1. 启动命令 `node server/index.js`，端口读 `PORT` 环境变量；
2. 把 `data/` 目录挂成持久卷，否则重启后所有碑会消失；
3. 平台的反代要放行 WebSocket 升级。

## 碑上的照片与声音

立碑的时候可以给他放一张照片、留一段他的声音。两样都可以留空。

- **照片**：在浏览器里先缩到最长边 900 像素、转成 JPEG 再传，所以手机随手拍也不会撑爆。放哪儿由立碑的人自己选：
  - 「嵌在碑上」：照片压在碑面顶部，名字和那行字往下让一截，像真的墓碑嵌照片；
  - 「立在碑前」：照片装在小相框里，立在碑脚左前方，走近能看清。
  点开碑（E）时，两种都还会在名字下面再显示一次。
- **声音**：可以在页面上直接录一段（八秒自动停），也可以选一个现成的音频文件。碑立好之后，走进三米会响，走开就停；同一块碑走开再回来会重新响一次。

**立完还能改**：读自己的碑，面板底下有一个「改这块碑」，点开就是立碑那张表单，只是字段都填好了。名字、那行字、碑后面的故事、碑型、遗物、声音、照片放哪儿都能改，改完碑会当场重画一遍；**位置不能改**——它已经站在那儿了，挪位置等于重新立一座。换照片或换录音时，旧的文件会从 `data/uploads/` 里删掉（除非还有别的碑在用同一份）。

**立错了怎么办**：读碑面板底下有两个只对作者可见的按钮——「让它沉睡」和「拆掉这座碑」。拆掉要点两次（第二次按钮会变成「真的拆掉？它不会再回来了」），拆完碑从所有人的屏幕上消失，照片和录音也从 `data/uploads/` 里删掉，找不回来。

上传走 `POST /api/upload`，服务端按**文件头**判断类型（不看客户端声明的 MIME），只收 `jpg / png / webp` 和 `webm / ogg / m4a / mp3`；照片解码后不超过 500KB，音频不超过 1.2MB；同一个地址每分钟最多 4 次。文件落在 `data/uploads/`，通过 `/uploads/<uuid>.<ext>` 读回来。

```text
data/
  graves.json          墓碑档案
  uploads/             照片与录音
```

备份要连 `uploads/` 一起备——只备 `graves.json` 的话，碑还在，照片和声音会变成 404。

## 回声的钥匙

立碑时在「回声用谁的声音」那一栏填三样：接口地址、你自己的密钥、模型名。任何 OpenAI 兼容的 `/chat/completions` 都行（官方、DeepSeek、Moonshot、通义、自建）。

这三样只存在你**这一台浏览器**里（`localStorage`，按碑的 id 分开存），不上传服务端、不进墓碑档案、别人的浏览器读不到。于是：

- 只有立碑的人、在自己这台机器上，能听见这块碑说话；
- 换浏览器或清缓存，钥匙就没了——和「换浏览器＝换身份」是同一个代价；
- 别人走到这块碑前按 R，会看到「这块碑的回声只在立碑的人手里」。

**想让所有访客都能听见**，就用墓园自己的公共钥匙兜底（`config/echo.json` 或环境变量）。请求里没带钥匙时，服务端才会用这份：

```powershell
copy config\echo.example.json config\echo.json
# 填 baseUrl / apiKey / model
```

或者：

```powershell
$env:ECHO_BASE_URL="https://api.deepseek.com/v1"
$env:ECHO_API_KEY="sk-..."
$env:ECHO_MODEL="deepseek-chat"
$env:PORT="8899"; npm start
```

**密钥怎么走**：浏览器把钥匙随请求发给自己的服务端，服务端在内存里转给上游，用完即弃——不落盘、不写日志、不回显。上游地址只放行 `https`（本机 `127.0.0.1` 的 `http` 例外），内网地址一律拒绝（防 SSRF）。`config/echo.json` 已加进 `.dockerignore`。

没有真 key 也能验证链路：

```powershell
node scripts\mock-echo.mjs      # 假上游，8898
$env:ECHO_BASE_URL="http://127.0.0.1:8898/v1"; $env:ECHO_API_KEY="mock"
node scripts\echo-probe.mjs     # 立一座带声音描述的碑，并打一次回声接口
```

## 线上部署

公网入口：`https://linkaoai.com/`（直接访问 IP `http://45.205.25.83/` 也可用，但会跳转到域名）。

服务器是 Ubuntu 24.04、Node 22、Nginx 反代到本机 `127.0.0.1:8899`，systemd 服务名 `world-cemetery`。档案、上传和备份都在 `/opt/world-cemetery`：

```bash
sudo systemctl status world-cemetery    # 看是否在跑
sudo systemctl restart world-cemetery   # 改完服务端代码后重启
sudo journalctl -u world-cemetery -n 50 # 看最近的日志
sudo grep CC_ADMIN_KEY /opt/world-cemetery/.env  # 取管理员 key，只在服务器上执行
```

- 数据：`/opt/world-cemetery/data/graves.json`、`accounts.json`、`secret.txt`、`uploads/`
- 自动备份：服务启动时和每 24 小时一份，放在 `/opt/world-cemetery/backups`，保留 7 份
- Nginx：`/etc/nginx/sites-available/world-cemetery`，`/live` 单独带 WebSocket 升级头
- TLS：Let's Encrypt 证书，certbot 自动续期；Cloudflare 用 Full 模式回源

`.env` 里是运行时密钥，不进源码包，也不进 Git。迁移或重装时，`data/` 整个目录一起带走；`backups/` 必须在服务启动前存在，否则 systemd 会以 `226/NAMESPACE` 拒绝启动。

## 前端可用性（v1.6）

- 立碑与回声面板的主操作吸在滚动区域底部；名字、碑文、故事和声音描述有实时字数提示。
- 提亮次级文字，统一键盘焦点；名录使用原生按钮，打开后可直接用 Enter 选择，弹层有 dialog 语义和焦点恢复。
- 触控层级低于读碑与名录；面板、摇杆和动作键适配手机安全区，开场页在小高度设备上可滚动。
- 立碑和改碑等待服务端 `raised / edited / reject` 后才恢复按钮，不再靠固定 800ms；断线时解锁，并提醒先确认结果再重试。

验证覆盖真实浏览器的桌面与 449×673 窄视口：读碑、名录键盘选择、触控遮挡、字数提示、重复提交拦截和公网资源一致性。真实手机上的录音与触控手感仍建议真机过一遍。

## 声音地理与一树一碑（v1.7）

墓园的环境声不再只有一层风。走在空地上，风是主角；走进林子，落叶的细响抬起来；靠近湖岸，浪声和水面上的低响慢慢浮上来。三层声音常驻，只按位置交叉调音量，不新建节点；整片声音还会经过一层低通，走进浅水时连脚步都会闷下去。湖面、林下和空地的比例会写进运行状态 `env`，便于核对。

碑前的声音现在有左右方位：站在碑左边听见它在右边，转过身后方位也跟着变。远处献光的钟声本来就有方位，两者现在用同一个判断。

树葬补上了最初说的“一棵树一个纪念”：服务端按树干坐标判断，同一个树位只能有一座碑；第二座会被拒绝，提示「这棵树已经有人靠着。换一棵吧。」立碑面板在走到已占用的树下时会变淡，按压也会得到同一句提示。已有的同树碑保留，不做迁移；这条规则只约束以后。

验证：在空地为 `wind=1`，林心为 `forest=1`，浅水边为 `water≈0.67`、`wet≈0.79`；同一座碑在玩家左侧时 `soundPan=-1`，右侧时为 `1`。真实提交第一座树葬成功后，第二座同树位被服务端拒绝；两座测试碑均已删除，数量恢复 15。

## 已知边界

- 身份是「一个名字 + 一句只有你知道的话」，不是邮箱也不是密码链接。这意味着：**没有找回、不能改名、名字先到先得**。忘了那句话，账号就进不去了（碑还在，只是你动不了它）。这是刻意的取舍——这里不想收集邮箱，也不想让你为一块碑去记一串验证码。
- 拆碑不可逆：没有回收站、没有软删除，拆掉的碑和它的照片录音直接从磁盘上消失。别人拆不了，但也救不回来。
- 改碑只改内容，不改位置；改完其他在线的人会看到那块碑在原地重画一遍。碑被别人读着的时候改，读的人面板会跟着刷新。
- 墓碑上限每人 12 座，同一位置 2.6 米内不能重叠，这些规则在前端和后端各校验一次。
- 实时同步是位置广播（每秒 12 次），适合几十人在同一片墓园里走动；上千人需要换成空间分区广播。
- 文字只做长度与控制字符清洗，没有敏感词过滤。**照片和录音只校验格式与大小，没有内容审核**——一张不该出现的图会被永久挂在某座碑前。开给陌生人之前必须补内容审核。
- 上传的图片和音频是公开可访问的静态文件（`/uploads/` 下不可猜的 uuid，但拿到链接就能看）。碑本身就是公开的，所以这与设计一致；但不要把私人照片放上去当成私密存储。
- 手机支持左半屏移动、右半屏视角和「读 / 立 / 名录」；录音、回声等完整操作仍建议用桌面键鼠。
- 回声的回复完全由上游模型生成，墓园只能约束提示词，不能保证它不说错话。目前的取舍是：对话不落库（保护来的人，也保护被纪念的人），代价是出事之后无从追查。真要开放给陌生人，得先补两件事：把每轮问答以脱敏形式留一份短期日志，和一条举报入口。
- 水是一层带水纹贴图的平面加一道月亮倒影，不是真反射；夜里很暗，走到岸边才看得出是水。天葬的灯不做遮挡，走进林子里可能被树冠挡一半。
